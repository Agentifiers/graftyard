# Wire census: GitHub surfaces and cross-cutting conventions

Captured 2026-10-23. Labels: [source] means read in a spec or source file, or captured live on the wire with the command shown; [doc] means official GitHub or git documentation or the official GitHub blog or changelog; [secondary] means a third-party writeup; [inference] means reasoning.

## Answer

GHES 3.22, the newest GHES description in github/rest-api-description, has 1,105 REST operations on 718 paths in 44 categories. api.github.com has 1,242 operations in 51 categories. Eleven categories with 184 operations exist only on dotcom, and most of them are Copilot, agents, and Codespaces. Four categories with 170 operations exist only on GHES, and 141 of those are `enterprise-admin`. The GHES 3.22 GraphQL schema has 937 object types, 24 Query fields, and 240 Mutation fields. The GHES webhook surface has 78 events and 272 event-action pairs. Two REST API versions are live on both dotcom and GHES 3.22: `2022-11-28` (default, supported until 2028-03-10) and `2026-03-10`. The operation count is the same in both versions, because the second version changes payloads, not paths. Git traffic is narrower than REST. github.com advertises only `ls-refs` and `fetch` under protocol v2. It advertises no `bundle-uri`, `object-info`, or `packfile-uris`. Push still uses protocol v0 `receive-pack` with `atomic`, `push-options`, and `report-status-v2`. Three conventions will bite a compatible server hardest. First, node IDs are opaque, but the new format packs the repository database id into them. Second, numeric ids already exceed 2^36, and GraphQL `databaseId: Int` is deprecated because of this. Third, since 2026-10-02 dotcom installation tokens are about 520 characters long and are stateless JWTs. GHES still issues 40-character tokens.

```

python3 scripts/census.py --refresh  # re-resolves the newest commit and GHES release
```

The script pins github/rest-api-description at commit `755ee33b4a81d51f6f07a902cce26cbec3b822f2` (2026-10-18), records the sha256 of every downloaded file, and writes `research/surfaces.json` with 81 entries. Two consecutive runs produced byte-identical output (sha1 `8553fea2...`).

### B. REST conventions every endpoint follows

11. The client selects the API version with the `X-GitHub-Api-Version` request header. Without the header, the server defaults to `2022-11-28`. An unknown version returns 400 and a retired version returns 410. Versions closing down send `Deprecation` and `Sunset` headers. A version stays supported for 24 months after its successor ships. Additive changes land in every supported version [doc] (https://docs.github.com/en/rest/about-the-rest-api/api-versions, https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api). Responses echo `x-github-api-version-selected: 2022-11-28` [source] (live `curl -I https://api.github.com/meta`).
12. GHES versions are decoupled from REST API versions, and GHES 3.22 supports both `2026-03-10` and `2022-11-28` [doc] (https://docs.github.com/en/enterprise-server@3.22/rest/about-the-rest-api/api-versions).
13. `2026-03-10` breaking changes include these. The `rate` property is removed from `GET /rate_limit`. Directory listings report submodules as `type: submodule`. `use_squash_pr_title_as_default` is removed. `authorizations_url` is removed from `GET /`. The remnants of the `beta` media type are removed. `DELETE /app/installations/{id}` returns 202 instead of 204 [doc] (https://docs.github.com/en/rest/about-the-rest-api/breaking-changes).
14. The base media type is `application/vnd.github+json`. Custom media types take the form `application/vnd.github.PARAM+json`. Commits and pulls accept `diff`, `patch`, and `sha`. Issue and comment bodies accept `raw`, `text`, `html`, and `full`. Contents accepts `raw`, `html`, and `object` [doc] (https://docs.github.com/en/rest/using-the-rest-api/getting-started-with-the-rest-api, https://docs.github.com/en/rest/repos/contents, https://docs.github.com/en/rest/commits/commits, https://docs.github.com/en/rest/issues/issues). Responses carry `x-github-media-type: github.v3; format=json` [source] (live probe).
15. Contents API limits: a directory listing returns at most 1,000 files. Files over 1 MB support only the `raw` and `object` media types. Files over 100 MB are not supported [doc] (https://docs.github.com/en/rest/repos/contents).
16. Pagination uses the `link` header with `rel` values `prev`, `next`, `first`, and `last`. Each paginated endpoint uses `page`, `before`/`after`, or `since`. The default page size is 30 and most endpoints cap `per_page` at 100. An oversized `per_page` is silently clamped, with no error [doc] (https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api). The docs' example link URLs use `/repositories/{id}/...`, not owner and name [doc] (same page). In the dotcom spec, 256 operations declare `per_page` with a default of 30 and no machine-readable maximum, 38 take `before`, and 36 take `after` [source].
17. Conditional requests: most endpoints return `etag` and many return `last-modified`. When a correctly authorized request gets a `304`, it does not count against the primary rate limit. Conditional requests on unsafe methods are unsupported unless an endpoint documents them. Polling endpoints may send `x-poll-interval` [doc] (https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api). Live `/meta` returned a weak ETag (`W/"..."`) and `cache-control: public, max-age=60, s-maxage=60` [source].
18. Primary rate limit headers are `x-ratelimit-limit`, `-remaining`, `-used`, `-reset` (epoch seconds), and `-resource`. The defaults are 60 requests per hour unauthenticated, 5,000 per user, 1,000 per repository for `GITHUB_TOKEN`, and a separate bucket of 3,000 per minute for authenticated LFS. Exceeding a limit returns 403 or 429 with remaining set to 0. Secondary limits return 403 or 429, sometimes with `retry-after`. The secondary limits are 100 concurrent requests, 900 REST points per minute per endpoint (GET costs 1, writes cost 5), 90 CPU-seconds per minute, and 80 content-creating requests per minute or 500 per hour. The docs warn that rate limit values can differ between responses because requests are served in multiple regions [doc] (https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).
19. GHES disables rate limits by default. Admins can enable primary and secondary limits per instance [doc] (https://docs.github.com/en/enterprise-server@3.22/rest/using-the-rest-api/rate-limits-for-the-rest-api, https://docs.github.com/en/enterprise-server@3.22/admin/configuring-settings/configuring-user-applications-for-your-enterprise/configuring-rate-limits).
20. Error body shape. `basic-error` has the fields `message`, `documentation_url`, `url`, and `status`, and `status` is a string. `validation-error` adds `errors[]` with `resource`, `field`, `code`, `message`, `index`, and `value` [source] (components/schemas in the dotcom description). Live 404 and 422 bodies match, for example `{"message":"Not Found","documentation_url":"...","status":"404"}` [source]. The `errors[].code` values are `missing`, `missing_field`, `invalid`, `already_exists`, `unprocessable`, and `custom`. Invalid JSON returns 400 "Problems parsing JSON" [doc] (troubleshooting page).
21. The 404 rule. An unauthorized request for a private resource gets 404, not 403, so the response does not confirm that the resource exists. An unsupported HTTP method also gets 404, not 405, and so does a trailing slash [doc] (https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api). Apps can read `X-Accepted-GitHub-Permissions`, and classic tokens can read `x-oauth-scopes` and `x-accepted-oauth-scopes` [doc] (same page) [source] (live 404 response headers).
22. Every request needs a `User-Agent`. A request without one is rejected, and an invalid one returns 403 [doc] (getting-started page). The API times out a request after 10 seconds. GraphQL timeouts return 502 or 504 [doc] (troubleshooting page, https://docs.github.com/en/graphql/overview/rate-limits-and-query-limits-for-the-graphql-api).
23. Redirects. Clients must follow 301, 302, and 307 [doc] (best-practices page). A renamed repository in the API returns `301` with `location: https://api.github.com/repositories/2126244` and a body of `{"message":"Moved Permanently","url":...}` [source] (live `GET /repos/twitter/bootstrap`). Over git smart HTTP, the same old name returns `200` with the advertisement served directly, not a redirect [source] (live `info/refs`). The docs say git operations on the old name "continue to function as if made on the new location". Creating a new repository with the old name breaks the redirect. Actions `uses:` references are not redirected [doc] (https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository, https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository).
24. Hypermedia. Resources carry `*_url` fields that are RFC 6570 URI templates, and clients are told not to construct or parse URLs [doc] (getting-started page, best-practices page). Archive endpoints return a 302 to `codeload.github.com/{o}/{r}/legacy.tar.gz/{ref}`. `github.com/{o}/{r}/raw/{ref}/{path}` returns a 302 to `raw.githubusercontent.com` [source] (live probes).
25. Timestamps in responses are UTC ISO 8601. Write paths accept an ISO 8601 offset, a `Time-Zone` Olson header, or the user's last known timezone [doc] (https://docs.github.com/en/rest/using-the-rest-api/timezones-and-the-rest-api).
26. Node IDs come in two formats. The legacy format is base64 of `NN:TypeNameID`, for example `MDQ6VXNlcjM0MDczMDM=`, which decodes to `04:User3407303`. The new format is a type prefix plus `_` plus a base64url payload, for example `U_kgDOADP9xw`. Old objects keep legacy IDs unless the request sends `X-Github-Next-Global-ID: 1`. Clients must treat both formats as opaque [doc] (https://docs.github.com/en/graphql/guides/migrating-graphql-global-node-ids). GitHub announced the format change in 2021 as a three-phase, nine-month rollout [doc] (https://github.blog/news-insights/product-news/new-global-id-format-coming-to-graphql/). Today, live `git/git` still returns the legacy repository ID `MDEwOlJlcG9zaXRvcnkzNjUwMg==`, while a new check run returns `CR_kwDNjpbPAAAAG_DLe18` [source].
27. The new node ID payload is MessagePack. `U_kgDOADP9xw` decodes to `[0, 3407303]`, and 3407303 is the user's database id. `CR_kwDNjpbPAAAAG_DLe18` decodes to `[0, 36502, 120003984223]`, the repository id followed by the check run id. `WFR_kwLN...` decodes to `[2, 36502, 40038635505]` [source] (decoded locally). The meaning of the first element is not documented [inference].
28. Integer ids. The dotcom spec marks 278 integer schema properties `format: int64`, and 3,076 integer properties have no format [source]. A live check run id is 120,003,984,223, a check suite id is 108,528,345,928, and a workflow run id is 40,038,635,505 [source]. GraphQL defines `scalar BigInt` "encoded as a string". The dotcom schema has 73 `databaseId: Int` fields and 31 `fullDatabaseId: BigInt` fields. Nine `databaseId` fields are deprecated "because it does not support 64-bit signed integer identifiers", and the latest removal date is 2027-01-01 [source] (dotcom schema). JSON numbers above 2^53 - 1 lose precision in JavaScript clients such as Octokit, and GitHub has not published a ceiling [inference].
29. Token formats. The prefixes are `ghp_`, `github_pat_`, `gho_`, `ghu_`, `ghs_`, and `ghr_` [doc] (https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github#githubs-token-formats). The 2021 design uses a `gh` prefix, the token-type letter, and `_`. It has 30 base62 random characters (178 bits) and a CRC32 checksum, base62-encoded with zero padding, in the last 6 characters, so tokens can be validated offline [doc] (https://github.blog/engineering/platform-security/behind-githubs-new-authentication-token-formats/).
30. Since 2026-10-02, every new dotcom installation token, including Actions `GITHUB_TOKEN`, is a stateless `ghs_APPID_JWT`. It is about 520 characters long and contains two dots. GitHub's recommended match regex is `ghs_[A-Za-z0-9\.\-_]{36,}`. The override header `X-GitHub-Stateless-S2S-Token` will be ignored after 2026-11-30. GHES is not affected [doc] (https://github.blog/changelog/2026-10-02-stateless-github-app-installation-tokens-rolled-out, https://github.blog/changelog/2026-05-15-github-app-installation-tokens-per-request-override-header).
31. Actions and other secrets use libsodium `crypto_box_seal`, a sealed box on X25519 that a client builds with a public key fetched from the API. The `encrypted_value` is base64 and is sent with the `key_id` [doc] (https://docs.github.com/en/rest/guides/encrypting-secrets-for-the-rest-api). The public-key schema requires `key_id` and `key`. Dotcom has 11 `.../public-key` operations covering Actions, environments, Dependabot, Codespaces, agents, and private registries [source].
32. GHES URL layout. REST is `http(s)://HOSTNAME/api/v3` and GraphQL is `http(s)://HOSTNAME/api/graphql`. OAuth uses `HOSTNAME/login/oauth/*` and `HOSTNAME/login/device`. Raw content is at `HOSTNAME/user/repo/raw` [source] (github/docs `data/variables/product.yml` lines 381-406). In the GHES spec, the release-asset upload operation's server is `https://HOSTNAME/api/uploads`. On dotcom it is `https://uploads.github.com` [source]. The spec's default server protocol for GHES is `http` [source]. The Manage GHES API is at `HOSTNAME:ADMIN-PORT/manage/v1/` [doc] (https://docs.github.com/en/enterprise-server@3.22/rest/enterprise-admin/manage-ghes).
33. With subdomain isolation, GHES moves these path prefixes to their own subdomains: `/raw/`, `/codeload/`, `/uploads/`, `/assets/`, `/avatars/`, `/gist/`, `/media/`, `/notebooks/`, `/pages/`, `/reply/`, `/viewscreen/`, the Docker registry, and `/_registry/{npm,rubygems,maven,nuget}/`. `containers.HOSTNAME` exists only with isolation. Isolation requires a wildcard DNS record and a TLS certificate with SANs for both `HOSTNAME` and `*.HOSTNAME`. Once it is enabled, the old paths may return 404 [doc] (https://docs.github.com/en/enterprise-server@3.22/admin/configuring-settings/hardening-security-for-your-enterprise/enabling-subdomain-isolation).
34. GHES returns `X-GitHub-Enterprise-Version: <version>.0` on REST responses [doc] (github/docs `content/rest/enterprise-admin/index.md` lines 92-96). GHES `GET /meta` has the properties `verifiable_password_authentication` (required), `packages`, `domains`, and `installed_version`. Dotcom `/meta` has 18 properties, including the IP-range lists `hooks`, `web`, `api`, `git`, `pages`, and `actions`, plus `ssh_key_fingerprints` and `domains` [source] (`api-overview` schema in both descriptions). On 2026-10-22, GitHub added new Actions blob-storage hosts to `/meta` [doc] (https://github.blog/changelog/2026-10-22-meta-api-endpoints-updated-for-actions-blob-storage).
35. GraphQL limits. Users get 5,000 points per hour. A query costs its connection requests divided by 100, with a minimum of 1. Every connection needs `first` or `last` between 1 and 100. A call may touch at most 500,000 nodes. Secondary limits allow 2,000 points per minute, with a query costing 1 and a mutation 5. A primary limit breach returns `200` with an error body. A secondary breach returns `200` or `403` [doc] (https://docs.github.com/en/graphql/overview/rate-limits-and-query-limits-for-the-graphql-api).
36. Webhook delivery headers are `X-GitHub-Hook-ID`, `X-GitHub-Event`, `X-GitHub-Delivery` (a GUID that stays the same on redelivery), `X-Hub-Signature` (SHA-1, legacy), `X-Hub-Signature-256` (HMAC-SHA256 hex digest), a `User-Agent` prefixed `GitHub-Hookshot/`, `X-GitHub-Hook-Installation-Target-Type`, and `X-GitHub-Hook-Installation-Target-ID`. GHES adds `X-GitHub-Enterprise-Version` and `X-GitHub-Enterprise-Host` [doc] (https://docs.github.com/en/webhooks/webhook-events-and-payloads, the GHES 3.22 variant of that page). The receiver must answer 2XX within 10 seconds or the delivery fails. Payloads are capped at 25 MB, and GitHub drops larger payloads [doc] (https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks).
37. GitHub never redelivers automatically. Deliveries from the last 3 days can be redelivered with `POST .../hooks/{hook_id}/deliveries/{delivery_id}/attempts` for repo and org hooks, or `POST /app/hook/deliveries/{delivery_id}/attempts` for apps. Deliveries are listed with `GET .../deliveries` [doc] (https://docs.github.com/en/webhooks/using-webhooks/handling-failed-webhook-deliveries, https://docs.github.com/en/webhooks/testing-and-troubleshooting-webhooks/redelivering-webhooks) [source] (9 delivery operations in the dotcom spec).
38. OAuth device flow. `POST /login/device/code` returns `device_code` (40 characters), `user_code`, `verification_uri`, `expires_in=900`, and `interval=5`. The client polls `POST /login/oauth/access_token` with `grant_type=urn:ietf:params:oauth:grant-type:device_code`, and polling too fast returns `slow_down`. The token responses are form-encoded by default, and JSON or XML is returned according to `Accept` [doc] (https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps).

### C. Git wire conventions

39. Smart HTTP uses `GET $GIT_URL/info/refs?service=git-upload-pack|git-receive-pack`, `POST $GIT_URL/git-upload-pack`, and `POST $GIT_URL/git-receive-pack`, and clients request v2 with the `Git-Protocol` header [doc] (https://git-scm.com/docs/gitprotocol-http). github.com serves these with and without the `.git` suffix. The responses carry `content-type: application/x-git-upload-pack-advertisement`, `cache-control: no-cache, max-age=0, must-revalidate`, `expires: Fri, 01 Jan 1980`, and `server: GitHub-Babel/3.0`. Dumb HTTP is refused: `info/refs` without `service` returns 403 and `/HEAD` returns 404 [source] (live probes).
40. Anonymous `info/refs?service=git-receive-pack` returns `401` with `WWW-Authenticate: Basic realm="GitHub"` and a body of "No anonymous write access." [source]. An OAuth `gho_` token worked as the Basic password with an arbitrary username [source] (live authenticated probe).
41. The github.com protocol v2 advertisement is identical over HTTPS and SSH [source]. Commands: `GIT_TRACE_PACKET=1 git ls-remote https://github.com/git/git` and `git ls-remote git@github.com:git/git.git`, git 2.50.1, 2026-10-23.

```
version 2
agent=git/github-f6e509caf74d-Linux
ls-refs=unborn
fetch=shallow wait-for-done filter
server-option
object-format=sha1
```

42. Git defines v2 commands and capabilities that github.com does not advertise: `object-info`, `bundle-uri`, `session-id`, `promisor-remote`, and the fetch features `ref-in-want`, `sideband-all`, and `packfile-uris` [doc] (https://git-scm.com/docs/gitprotocol-v2) [source] (absent from the capture above).
43. The v0 upload-pack capabilities over HTTP are `multi_ack thin-pack side-band side-band-64k ofs-delta shallow deepen-since deepen-not deepen-relative no-progress include-tag multi_ack_detailed allow-tip-sha1-in-want allow-reachable-sha1-in-want no-done symref=HEAD:refs/heads/master filter object-format=sha1`. The SSH advertisement is the same without `no-done` [source] (live captures).
44. The receive-pack advertisement, on an authenticated GET to a repository the user owns, is `report-status report-status-v2 delete-refs side-band-64k ofs-delta atomic object-format=sha1 quiet agent=github/spokes-receive-pack-<sha> session-id=<id> push-options` [source]. `push-cert` is absent. The session-id value has the same shape as an `X-GitHub-Request-Id`, and the agent string names GitHub's Spokes replication tier on the push path [inference].
45. SSH uses user `git` at `git@github.com:OWNER/REPO.git`. `ssh -T git@github.com` prints "Hi USER! You've successfully authenticated, but GitHub does not provide shell access." and exits with status 1 [source] (live). `ssh.github.com` port 443 is an alternate endpoint. Its host key is stored as a separate `known_hosts` entry, so BatchMode failed there with "Host key verification failed." [source]. I did not compare the two host keys.
46. LFS. The batch endpoint is `POST <remote>.git/info/lfs/objects/batch` with `Accept` and `Content-Type: application/vnd.git-lfs+json`, and a wrong Accept header returns 406. The locking API is `POST /locks`, `GET /locks?path=&id=&cursor=&limit=&refspec=`, `POST /locks/verify`, and `POST /locks/:id/unlock`. An SSH remote runs `ssh git@host git-lfs-authenticate <path> <upload|download>` to get an HTTP href and header [source] (git-lfs `docs/api/batch.md`, `locking.md`, `server-discovery.md` at commit `debca01a`). By default the batch API handles 100 objects per request on GitHub [doc] (REST rate limits page).

## Implications for the design

- [inference] Treat the GHES 3.22 description, not dotcom, as the REST compatibility target. The 184 dotcom-only operations are mostly Copilot, agents, and Codespaces, and GHES clients cannot assume them. The 141 `enterprise-admin` operations are part of the GHES contract, and the admin tooling of self-hosted customers will call them.
- [inference] The conformance oracle for REST shape can be the pinned OpenAPI file itself, by validating responses against `ghes-3.22.json` for both API versions. `census.py` already pins and hashes it.
- [inference] Advertise `X-GitHub-Enterprise-Version` and `/meta.installed_version` as a real GHES version string, such as `3.22.0`. Clients gate features on these values, so the version Graftyard claims is a compatibility promise, not a label. Check `research/clients.md` for the heuristics.
- [inference] Node IDs must be opaque to clients but can carry routing data for Graftyard. GitHub's new format embeds the repository id, which lets a cell router resolve `node(id:)` without a global lookup. Copy that structure, and accept legacy-format IDs as input.
- [inference] Every numeric id column should be i64 end to end. Allocation should stay below 2^53 so Octokit-class clients keep working. GraphQL should expose `fullDatabaseId: BigInt` as a string.
- [inference] Token validation should check the prefix and CRC32 offline first, at the edge, before a database lookup. Stateless JWT installation tokens remove the database lookup from the hot path, which is an availability win. Plan for both the 40-character and the roughly 520-character forms, and size headers, proxies, and columns for the long form.
- [inference] Git v2 only needs `ls-refs` and `fetch` with shallow, filter, and wait-for-done support to match github.com. Push must support `atomic`, `push-options`, and `report-status-v2`. `bundle-uri` and `packfile-uris` are optional extras that could offload clone traffic to S3 without breaking parity.
- [inference] Renames need a durable alias table that both the API (301 to `/repositories/{id}`) and git (transparent 200) consult. Creating a repository at an old name must delete the alias.
- [inference] Rate-limit counters may be approximate and regional. GitHub documents that remaining counts can vary between responses. That allows per-cell counters without global coordination.
- [inference] Webhook delivery is at-least-once with a stable `X-GitHub-Delivery` GUID, a 10-second budget, a 25 MB cap, and 3 days of redeliverable history. The outbox design must keep delivery records for at least 3 days and expose the attempts API.
- [inference] Subdomain isolation forces wildcard DNS and TLS in self-hosted and BYOC installs. The managed mode needs the same split so that raw, codeload, uploads, and pages content runs on separate origins.

## Open questions

- The meaning of the first MessagePack element in new node IDs (0 or 2) and the full list of type prefixes are undocumented. I measured only `U_`, `CR_`, `CS_`, and `WFR_`.
- I did not capture GHES's own git advertisement. GHES may advertise a different v2 capability set or agent than github.com.
- I did not verify GHES 3.22's runtime `X-GitHub-Api-Version` default or which version strings it rejects. The docs say it matches dotcom.
- The GHEC description (`descriptions/ghec`) was not counted.
- The spec defines 78 GHES webhook events and the docs page lists 76. I did not reconcile the two missing events.
- GitHub publishes no maximum for numeric ids, and nothing shows how close any table is to 2^53.
- The packages registries (container, npm, maven, nuget, rubygems) and pages serving have null counts. They follow external protocols (OCI distribution, npm, Maven layout, NuGet v3, RubyGems) that this slice did not enumerate.
