### The GitShard image

The deployed versions of all six `GitShard` scripts run `registry.cloudflare.com/<account>/graft-m1-wp6-bed-gitshard-git@sha256:b7bbc1f6…b43e`. That covers `graft-m1-site-a/b/c` and also the lin24b scripts `graft-m1-lin-a/b/c`. So lin24b depends on this image as well as the site. The registry stores the image under the bed's repository name.

What the evidence shows:
- Deleting a container application or a Worker does not touch the registry. After `graft-m1-wp5`'s script and container application were deleted, its tag `wrangler-mvy2psbi` (the same digest) still resolved with 200.
- Deleting other tags does not remove shared blobs. 27 tags were deleted, and the kept manifest and all six of its blobs answer 200 in `graft-m1-wp6-bed-gitshard-git` afterwards (`check-kept-images.sh`, exit 0).
- Cloudflare's docs say an image leaves the registry only through `wrangler containers images delete`.

No test here deleted the bed's own script or its application, and no document says the registry repository named after a script outlives that script. So `graft-m1-wp6-bed` and its application stay. Nothing binds them, and they cost nothing while idle (0 instances). To remove them later safely, first push the image under a neutral name with `wrangler containers push`, then redeploy the site through a site day.
