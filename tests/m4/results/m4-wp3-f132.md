## What it proves

F132 (`decisions/OPEN-QUESTIONS.md`): `ActionsTrigger` reads a called file through `reusable::called_file`, as the edge's dispatch does. A push whose workflow `uses:` another repository's workflow is planned, where before it was skipped.

- `m3org/f132-<tag>-shared`, public, holds `called.yml` (`on: workflow_call`):
  - at tag `v1`, printing `version=tag`;
  - on a branch also named `v1`, printing `version=branch`.
- `m3org/f132-<tag>` gets `caller.yml` (`on: push`, one job that `uses: m3org/f132-<tag>-shared/.github/workflows/called.yml@v1`), pushed to `main`. That push is the check.

**Pass:**
- exactly one push run of `caller.yml`, at the pushed commit on `refs/heads/main`;
- its one job, `call / deploy`, succeeds on an unmodified runner;
- the job prints `version=tag` (the tag wins over the branch);
- the job's ID token's `job_workflow_ref` is `m3org/f132-<tag>-shared/.github/workflows/called.yml@refs/tags/v1`;
- its `workflow_ref` is the caller's, `m3org/f132-<tag>/.github/workflows/caller.yml@refs/heads/main`;
- its `event_name` is `push`;
- no token appears in the log.

Before `push-calls`, the trigger skipped this workflow ("a call into another repository is not taken from a push or pull request yet"), so the push started no run.
