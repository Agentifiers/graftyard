# M0-WP13: token ceilings, tasks, the agent gate, and the trust view (2026-10-30)

This package extends the M0-WP10 prototype in `src/agent/`. It adds prototypes of `AgentTask` with `TaskKind`, `TaskApiState`, the task creation rules, the `graftyard_task` token request field, `AgentGate` in `Merge::decide` (with the A23 rule for an empty `requester`), and the `WriteScope` check on approve and merge (`design/DESIGN.md`, Shape, "Agent load and agent safety"). It also adds the trust view: `TrustView`, `Hidden`, `AuthorTrust`, `HIDDEN_CHARS`, and `AGENT_MEDIA_TYPE` (`design/AGENT-LAYER.md`, Shape, "Trust view"). It runs on the same Worker, `graft-m0-agent`, with one new script, `graft-wp13-hooks`, which receives every App's webhooks. No other script was deployed or redeployed. Nothing under `src/wp12/` was touched.

## L0-09: the trust view

**Run.** `node run/agent-l009.ts --k 8 --run r1 --oracle` against the deployed Worker (raw: `results/raw/wp13-l009-r1.jsonl`, `-summary.json`, `-oracle.json`, and the payload list `results/raw/wp13-l009-payloads.json`). There are 200 payloads (`run/agent-payloads.ts`), each hiding the marker `GYINJ<nnn>`:

- **50 HTML comments**, each in LF and CRLF form. Nested comments (`<!-- <!-- M --> -->`), the HTML5 closers `--!>` and `<!--->`, `--` inside a comment, comments split across lines inside one paragraph, in blockquotes, list items, and tables, unclosed comments in raw-HTML context, processing instructions, CDATA, declarations, and an unreferenced footnote.
- **70 invisible characters**: every zero-width and filler character in `HIDDEN_CHARS`, then every bidi control, each raw and as a hexadecimal or decimal reference. Also named references (`&shy;`, `&ZeroWidthSpace;`, `&zwj;`, `&lrm;`), the tag block (the marker spelled in tag characters), the variation-selector supplement, interlinear annotation marks, a Trojan Source line, and bidi controls inside code spans, fences, and link titles.
- **40 link titles**: markdown titles in `"…"`, `'…'`, and `(…)`, a title on the next line, escaped quotes, image titles, reference definitions with titles (including the `[//]: # (…)` comment idiom), and raw `title`/`alt` attributes on `a`, `abbr`, `img`, `span`, `kbd`, `sub`, and `p`.
- **40 collapsed blocks**: `<details>` in upper case, nested inside one with `open`, unclosed, split over lines, inside lists and blockquotes, holding tables or fences, and with a fake `</details>` inside a code span, a comment, a fence, or as `&lt;/details&gt;`.

Each payload went through four surfaces, 800 objects in all, each read back plain and under `application/vnd.graftyard.agent+json`:

- an issue body;
- an issue comment (half of them by mallory, a read-only user);
- a check run's `output.title`, `output.summary`, or `output.text` (in turn), posted by the confined vendor App;
- a commit message, pushed with real git and read back from the git object through `GET /commits/{sha}`.

For marker payloads, "absent from `visible`" means the marker string is gone. For invisible-character payloads, the hidden characters themselves are the injection, spread between the marker's letters, so it means no `HIDDEN_CHARS` character and no reference decoding to one is left.

**Oracle.** Each of the 130 non-character payloads was also rendered with GitHub's own renderer (`gh api /markdown`, gfm), and its text was checked with closed `<details>` reduced to their summary. GitHub hides the marker in 126 of them. GitHub shows it in 4: `x <!-- M --!> y` and `x <!--- M ---> y`, LF and CRLF, which CommonMark treats as text, not a comment. The trust view drops all 130 anyway, so it hides a superset of what GitHub hides: 0 payloads that GitHub hides appear in `visible`.

- **A23** (`decisions/DECISIONS.md`, "A PR with no recorded requester needs one more human approval"; `design/DESIGN.md`, Shape, `AgentGate`). `gateHolds` in `src/agent/decide.ts` counts distinct approvers with a gate row on the current head who are writers, not the requester, and not pushers to the head. ## What is real and what is modeled

**Real.**

- `decide`, `decideTask`, `decideMint`, the trust view, and the deny-list, all pure, run on every request in `graft-m0-agent`'s Durable Object, with folds in its SQLite.
- `git` 2.56 as the client for every push. In the container: `index-pack --strict`, the diffs, the ancestry checks (including "does the new tip contain an open agent PR's head"), `merge-tree` for `POST /merges`, and raw commit reads for `GET /commits/{sha}`.
- The token request and `token/scoped` as HTTP endpoints. Every token in L0-03 came from the host's own token request, not from the driver.
- Webhook deliveries: real HTTPS POSTs from the object's `waitUntil` to a separate script, with signatures verified at the receiver and arrival timed on Cloudflare's clock.
- Code Mode: a real Dynamic Worker per call (`worker_loaders`, `globalOutbound: null`), whose only capability is an RPC entrypoint with the token in `ctx.props`.
- The feed's edge checks in the Worker's fetch handler, in front of the objects.
- GitHub's own markdown renderer as the oracle for what a reader sees.

**Modeled.**

- **Consensus, tokens, `Authz`, rulesets, and the PR model** are modeled as in M0-WP10 ("What is real and what is modeled" there). Tokens are HMAC prototypes carrying the claims and permission sets, with no JWT, `jti` revocation, or `Tokens` shard. MCP's `Tokens` rows live in the object's SQLite. Grants are a fixture, and no `McpGrant` endpoint or consent flow was built (M0-WP15).
- **The feed.** Only the edge checks and a stand-in learner (`FeedMember`) that holds polls and counts `FEED_POLLS` per token and per IP inside one object. No events, cursors, followers, or placement (M0-WP12). "The leader sees zero" is measured on the prototype's leader stand-in.
- **The controller** is not built. Its webhook is `graft-wp13-hooks`, which records and verifies deliveries. The prompt is `Host.prompt()` (snapshot, writer comments, counts) read through a harness path, and it leaves out `AGENTS.md`. `/log` and the session page check permissions and answer 404, because no `SessionLog` is pushed.
- **Demotion** counts committed writes per actor in the fold's trailing minute and does not drive admission lanes. Drivers pace each human token under `DEMOTE_PER_MIN` (see edit 6).
- **`graft-mcp`** is two functions on the same Worker, not a separate script behind `graft-front`. Code Mode's `code_mode` read is not cached for 60 s.
- **Issues, comments, and check runs** are minimal: one fold row each, `issues: write` as the App ceiling, and no labels, reactions, or GraphQL reads of them. The trust view covers the four resources the row names, plus PR bodies.

## Proposed design edits

Every ambiguity the prototype had to resolve, with the sentence it proposes and the evidence. Edits to the agent block go into both `design/DESIGN.md` and `design/AGENT-LAYER.md` (AGENTS.md). Citations are by section.

1. **A ref write that merges an agent PR outside `Merge`.** `AgentGate` binds `Merge` of a PR with `AgentMeta`. A human with push access (or an MCP `Write` token) can land the PR's head on its base by `PATCH /git/refs`, `POST /merges`, or `git push`, and nothing in the agent block says the gate binds those. The prototype treats any ref update whose new tip contains an open agent PR's head, into that PR's base, as a merge of it: `Merge`'s agent refusal, the MCP `WriteScope` check, and the gate apply, and the PR closes as merged. Proposed, in the agent block, `AgentGate` doc comment: "A ref update of a PR's base whose new tip contains the PR's head is a `Merge` of that PR for these rules, from any surface; `validate` reports which open `AgentMeta` heads each new tip contains." Evidence: L0-03 widened cells and L0-15 (b), `POST /merges` refused.
2. **A23's count needs distinct approvers.** "one more such approval than `extra_human_approvals` asks" needs several gate rows, but `AgentGate` is one struct per PR. The prototype keeps every qualifying row on the current head and counts distinct `satisfied_by`. Proposed, in the agent block, `AgentGate` doc comment: "Each qualifying APPROVE writes a row; `Merge` counts distinct `satisfied_by` on the current head and needs `1 + extra_human_approvals`, plus one when `requester` is empty." Evidence: unit test "A23", L0-15 (d).
3. **Is the would-be requester's approval a qualifying one under A23?** With `requester` empty, nobody is excluded as requester, so the requester's approval writes a row and counts as one of two. The prototype does this, and that is A23's intent. Proposed, the same comment: "With `requester` empty, every writer's approval qualifies, the requester's included, which is why one more is needed." Evidence: L0-15 (d), `1 of 2 approvals`.
4. **What a non-writer edit does to the task, in task API terms.** "pauses the task until a writer reassigns it" names no `TaskApiState` and does not say what the host refuses. The prototype sets `waiting_for_user` and a host-owned pause flag, refuses the App's `PATCH` into a running state (409), refuses pushes as "no live task", and refuses `graftyard_task` minting. A writer's reassignment to the controller's bot clears the flag, sets `queued`, and moves `snapshot` to the reassignment's index. Proposed, in the agent block, `AgentTask` doc comment: "A title or body edit by a non-writer after the task's latest `Assigned` entry sets `waiting_for_user` and a host pause. While paused the task counts as not live for pushes and minting, and its App may set only `waiting_for_user` or a final state. A writer's reassignment to the controller's bot clears the pause and moves `snapshot` to that entry's index." Evidence: L0-09 pause rounds.
5. **Who is "a demoted actor" at task creation.** `DEMOTE_PER_MIN` counts writes, and task creates and cancels are writes, so a human writer who creates more than 60 tasks a minute demotes themselves and the 61st create is refused. A local L0-14 trial hit this: 39 of carol's 100 control creates were refused as demoted. Proposed, in the agent block, task-creation paragraph: "A demoted actor is one past DEMOTE_PER_MIN at the create's own entry, counting task commands." Or exclude task commands from the count. Evidence: the local trial (not kept), `classify` in `src/agent/classify.ts`, and the driver pacing in `run/agent-lib13.ts` (`Pace`) that keeps the run's writers under 55 writes a minute. [guess at the remedy]
6. **`requester` of a controller-created task, and its cap.** "with that entry's actor as `requester`" makes the assigning user the requester, so `TASKS_OPEN_PER_REQUESTER` counts controller tasks against whoever assigns issues. One triager assigning 100 issues blocks their own prompt tasks. The prototype counts them. Proposed: record in `design/AGENT-LAYER.md`, "Tasks and the activity feed", that "Controller-created tasks count toward the assigning user's open-task cap." Evidence: L0-14 control, 96 plus the fixture's 4 filled alice's cap, and the 97th was refused.
7. **Status codes for the task rules.** The API reference lists 422 for `agents_enabled` off, missing fields, a bad session, an existing session, and the cap, but not who gets 403. The prototype returns 403 for a creator that is not allowed (an installation token, an `AgentApp`'s user token, demoted, read-only, agent session, or the controller without its assignment) and for `PATCH` by another App, 422 for `cancelled` or `timed_out` in `PATCH`, and 409 for a final or paused task. Proposed, `design/AGENT-LAYER.md`, "API reference", `/tasks` post: add "403: credential may not create a graftyard_run task", and on `/tasks/{id}` patch: "403: not the task's App; 409: final or paused".
8. **`graftyard_task` with no `repositories`.** "every repository the token covers must be the task's repository or its workspace fork" refuses a request without `repositories` whenever the installation covers more. The prototype refuses it (422), so a caller must name the repositories. Proposed, the agent block, `AgentTask` doc comment: "A token request with `graftyard_task` must name `repositories`." Evidence: L0-14 "mint with every repository of the installation", 100/100 422.
9. **Paused and final tasks at minting.** "must name a live `GraftyardRun` task" is silent on paused tasks. The prototype refuses those too. Proposed: covered by edit 4.
10. **Which credentials count as "MCP-issued" and "an `AgentApp`'s".** `AgentGate` is written "only [by] an APPROVE review sent with a credential that is neither an `AgentApp`'s nor MCP-issued". A vendor App's user-to-server token (`ghu_` of the vendor App) is an `AgentApp`'s credential. The prototype gives it no gate and no Graftyard-run create. Proposed, the agent block, `AgentGate` doc comment: "an `AgentApp`'s credential includes its user-to-server tokens". Evidence: L0-14 "AgentApp's user token", unit test "task create".
11. **The trust view's grammar is unstated.** `Hidden` names four counts but not which constructs fill them. Implementing it raised these questions:
    - Comments: `--!>` closes a comment in HTML5, while GitHub's CommonMark renderer shows `x <!-- M --!> y` as text.
    - Reference definitions: titles live there too, and `[//]: # (…)` is the common comment idiom.
    - Attributes: `alt`, `aria-*`, and `data-*` carry hidden text like `title` does.
    - Collapsed blocks: a `</details>` inside code or a comment could close a block early.
    - Code: a numeric reference to a hidden character inside code is literal text.

    The prototype's rule (the header of `src/agent/trust.ts`) drops a superset of what GitHub hides. Proposed, in `design/AGENT-LAYER.md`, Shape, `TrustView` doc comment: "`visible` drops at least what GitHub's gfm renderer hides: comments (HTML5 closers included), processing instructions and declarations, every attribute except `href` and `src` (counted with link titles), titles of links, images, and reference definitions, unreferenced reference and footnote definitions, everything in a `<details>` without `open` but its first `<summary>` (an opening tag in code still opens), and HIDDEN_CHARS raw or as references outside code. Where it cannot tell what a reader sees, it drops more." Evidence: L0-09 oracle, 126 of 130 hidden by GitHub and 130 of 130 by the trust view.
12. **The prompt's issue snapshot and comments.** "comments only from human authors who can push" leaves open whether comments are snapshotted too. The prototype reads the issue at `snapshot` and comments as they are now. Proposed, `design/AGENT-LAYER.md`, journey A3, step 4: "comments from writers, as of the task's `snapshot`". [inference: otherwise a writer comment after assignment changes the prompt without a pause, which is allowed, but should be stated]
13. **The feed's per-IP and per-token limit across isolates.** `FEED_POLLS` counts concurrent polls per token and per IP, but the edge runs in many isolates. The prototype counts in the serving member, which sees every poll for its group. Proposed, `design/AGENT-LAYER.md`, Shape, activity feed doc comment: "FEED_POLLS is counted by the serving member, across its held polls, so a client spread over isolates still gets 429." Evidence: L0-15 over-limit, 100/100 429 from `FeedMember`.
14. **`metadata: read` on a task read.** Lists and states need `metadata: read`, and prompts need `contents: read`, but `GET /tasks/{id}` returns both. The prototype omits `prompt` without `contents: read` and returns 403 for an explicit prompt read. Proposed, `design/AGENT-LAYER.md`, "API reference", `task` object: "`prompt` is omitted without `contents: read`". Evidence: L0-15, 100/100 task reads 200 without `prompt`, and 100/100 prompt reads 403.
15. **Code Mode's deny-list contents.** "the same tool deny-list as `call`" is never listed. The prototype denies, for a `Write` grant, an `APPROVE` review, `PUT .../merge`, `POST /merges`, and auto-merge, and for every grant non-repository paths, GraphQL, and unnormalized paths. Proposed, `design/AGENT-LAYER.md`, Shape, `WriteScope` doc comment: "Without `WriteApproveMerge` the deny-list refuses APPROVE reviews, PR merges, `POST /merges`, auto-merge, and ref updates that would merge an agent PR (edit 1); `codemode.request()` takes repository REST paths only." Evidence: L0-15 (b).
16. **The flagged App's subscription to `graftyard_task`.** The design says no other App "can subscribe". GHES manifests accept event names freely, so the host must ignore it rather than reject it. The prototype sends the event only to the controller App, whatever others subscribe to. Proposed, the agent block, task-creation paragraph: "Other Apps' subscriptions to `graftyard_task` are ignored." Evidence: L0-14, 0 deliveries to the flagged App, which subscribes to `*` and `graftyard_task`.
