# M0-WP10: agent refusals and provenance on the base (2026-10-30)

`src/agent/` is a prototype of the agent block in `design/DESIGN.md`, Shape, "Agent load and agent safety", with the design's names: `ActorKind`, `AgentActor`, `AgentApp`, `AgentTask`, `SessionId` (string form), `Lease`, `LeaseEnforce`, `AgentPolicy`, `AgentGate`, `AgentMeta`, `ProtectedHits`, `ChangedPaths`, `Provenance`, `Source`, `TrailerKey`, `PROTECTED_PATHS`, `PATHS_MAX`, `EXCLUSIVE_MAX`, `TASK_IDLE`, and `SESSION_REFS`. It runs as its own script, `graft-m0-agent`, with one Durable Object class `AgentRepo` and its container, so nothing here touches another bed. No other script was deployed or redeployed.

**Why the container and not a local `git http-backend`.** The design's receive path is Graftyard's own receive-pack at the edge, with git's work (index-pack, connectivity, diffs) on a git cache shard container and refs from the fold. `git http-backend` would put git's receive-pack and its ref store in charge, and the hidden-ref rule would come from git's `hideRefs` instead of `decide` and the edge's advertisement. So the run uses the container under the object, as production would. The local mode runs the identical `Host` and `gitd` code and is used only for development and the unit-level shape capture (`results/raw/wp10-shapes.json`).

## Refusal shapes on the wire

The same `Refusal { rule, text }` from `decide` renders per surface (`results/raw/wp10-shapes.json`, captured verbatim):

- **git.** HTTP 200 with side-band `report-status`. Each refused ref gets `ng <ref> <text>`, and band 2 carries `remote: error: <text>`, which git prints as `! [remote rejected] <src> -> <dst> (refused: graftyard-workspace may push only refs/heads/graftyard/<uuid>/**)`. Lease and protected-path refusals name the lease and holder (`refused: pkg/auth/** is leased Exclusive by graftyard-agent (task 2222…) until <time>`) or the path (`refused: .github/workflows/x.yml is a protected path; agents may not change it`).
- **REST.** The action refusals the design lists as 403 return `403 {"message": "refused: agents may not …", "documentation_url"}`. Ref writes refused like a push (prefix, task, protected, lease, host-owned) return `422 {"message": "refused: …", "documentation_url": ".../git/refs", "status": "422"}`, GitHub's rule-violation shape. An unsatisfied `AgentGate` returns `405 {"message": "refused: graftyard/agent-gate is not satisfied for <sha>: <why>"}`, GitHub's "not mergeable" status.
- **GraphQL.** HTTP 200 with `data: {<mutation>: null}` and `errors: [{type, path, locations, message}]`. `type` is `FORBIDDEN` for action refusals and `UNPROCESSABLE` for ref-write refusals.
- **Permission ceiling, not `decide`.** An installation token that lacks the permission (`graftyard-agent` has `contents: read`, `statuses: read`, `actions: read`) gets GitHub's own `403 Resource not accessible by integration`, or GraphQL `FORBIDDEN` with that message, before `decide` runs. The drivers record these as `Ceiling`, and the run reports them separately (see B0-36).

## What is real and what is modeled

**Real.**

- `git` 2.56 as the client, for every push, clone, `--mirror`, `ls-remote`, and fetch.
- The smart-HTTP framing on the wire: `report-status`, side-band, and pkt-line `ls-refs`.
- `index-pack --strict` on every pushed pack, and git's own diffs, ancestry, `rev-list`, and notes tree.
- git's `upload-pack` for every fetch, with its `hideRefs` check of "our ref".
- A Cloudflare container under a Durable Object with `enableInternet: false`, and the object's SQLite holding the folds.
- The pure `decide`, its `classify`, and the trailer parser, on every request.
- The HTTP status and body shapes.

**Modeled.**

- **Consensus.** One object stands in for the group leader, so there is no quorum, no `Acked`, and no follower `verify`. The entry lock gives one command per entry.
- **Tokens.** They are HMAC prototype tokens that carry the claims a verified `ghs_`/`ghu_`/PAT would give. There is no JWT minting, no `jti` revocation, and no `Tokens` shard read.
- **`Authz` rows.** `AgentApp` rows, installations, and their permissions are a fixture in `deps`, not a chain read `fresh`.
- **Folds, rulesets, collaborators, and PRs** are minimal.
- **Rulesets** check only deletion and non-fast-forward.
- **The fork** shares objects by alternates in one container.
- **The pack** is not placed in R2 (no `PackStore::place`) and has no `PackRef`.
- **Admission.** It is classified and recorded, with no token bucket and no queueing.
- **Leases and tasks** are set up by the fixture and the cancel endpoint. The lease API was not built.
- **The REST and GraphQL handlers** cover only the listed actions, with GitHub's documented shapes and no byte-diff against GHES. GraphQL takes one mutation per request, with node ids as `PR_<n>`, `R_<owner/repo>`, and `REF_<repo>:<ref>`.
- **The v2 `fetch` command** is passed to git with `hideRefs`, so a want by object id of a hidden tip is served, as git and GitHub do. Only the listing is gated.

## Proposed design edits

Every ambiguity the prototype had to resolve, with the sentence it proposes and the evidence. Edits to the agent block go into both `design/DESIGN.md` and `design/AGENT-LAYER.md` (AGENTS.md). Citations are by section, because other agents are editing those files.

1. **Confined vendor Apps and "no live task" (contradiction between the row and the refusal list).** `build/BUILD-PLAN.md`, M0-WP10, B0-36, and `design/DESIGN.md`, "Build order from zero", the same row, ask both agent kinds to be refused "a push with no live task" and "a fork push after its task is cancelled". The refusal list in Shape, the agent block (`ActorKind` doc comment), names only "a Graftyard-run push with no live `AgentTask`", a confined vendor App has no `task` claim, and an External task "gets no prefix and no token" (`design/AGENT-LAYER.md`, "Tasks and the activity feed"). Evidence: `vendor/no-live-task/*` and `vendor/cancelled-task/git` accepted 400 of 400 in `results/raw/wp10-b036-b036r3-summary.json`. Proposed, either one of:
   - (a) Narrow the row, in `build/BUILD-PLAN.md`, B0-36, and the matching row in `design/DESIGN.md`, "Build order from zero": "a push with no live task and a fork push after its task is cancelled (Graftyard-run token only; a confined App is bound by `confine`)".
   - (b) Extend the rule, in the agent block, `ActorKind` doc comment: "a Graftyard-run push with no live `AgentTask`, and a confined App's push that names, through `X-Graftyard-Agent-Session`, an External task that is not live".

   Taking (b) does not make "no session" refusable without breaking vendors that never create tasks. The prototype recommends (a).

2. **What "outside the prefix" means for the task's own refs.** The refusal list says "a ref update outside its task's prefix (a third-party App's `confine` prefix)". `prefix` is `refs/heads/graftyard/<uuid>/`, and `confine` is a `RefPattern` such as `refs/heads/claude/**`, so one is a string prefix and the other a glob. The prototype matched `prefix + "**"` and `confine` as globs, so `refs/heads/graftyard/<uuid>` itself (no trailing segment) is outside. Proposed, in the agent block, `AgentTask` doc comment: "`prefix` is matched as the `RefPattern` `refs/heads/graftyard/<uuid>/**`, so a ref must have at least one segment after the session id". Evidence: `decide.ts`, `allowedPrefix`, and the unit test "push: prefix, live task, protected, host-owned".

3. **Tags and releases are two rules on a push.** "release and tag creation" is refused, but a tag push is also "a ref update outside its prefix". The prototype checks the tag rule first, so a tag push names `Release`, not `OutsidePrefix`. For the git "merge", a fast-forward of `main`, it names `OutsidePrefix`, because the refusal list has no git form of `Merge`. Proposed, in the agent block, `ActorKind` doc comment, after the list: "When a push breaks more than one rule, the refusal names the first in this order: host-owned ref, stale or missing object, tag creation, live task, prefix, ruleset bypass, protected hit, lease". Evidence: B0-36 table, rows Release and Merge.

4. **Bypass on a push is not in the list as a push rule.** "ruleset and bypass edits or use" covers use, but a push only uses a bypass when it is non-fast-forward or a deletion past a ruleset that lists the App. The prototype refuses that push with `Bypass` even inside the prefix. Proposed, in `design/AGENT-LAYER.md`, "GHES compatibility", row "Agent refusals in `decide`": add "a push that would need a ruleset bypass, refused even when the App is a listed bypass actor". Evidence: `*/bypass/git` 300 of 300 `Bypass`.

5. **REST status per refusal is unstated for ref writes and merges.** "GHES compatibility", "Agent refusals in `decide`", says 403 for the action list and "push rejection" for pushes, but REST ref writes (`POST`/`PATCH /git/refs`, `createRef`, `createCommitOnBranch`) and a `Merge` refused by `AgentGate` have no stated shape. The prototype used 422 with GitHub's rule-violation body for ref writes, 405 for an unsatisfied gate (GitHub's "not mergeable"), and GraphQL `FORBIDDEN` or `UNPROCESSABLE`. Proposed, the same row: "REST ref writes get 422 with the refusal text as `message`; `Merge` without `AgentGate` gets 405; GraphQL gets an `errors` entry of type `FORBIDDEN` for action refusals and `UNPROCESSABLE` for ref refusals" [inference: GHES's documented codes for these endpoints]. Evidence: `results/raw/wp10-shapes.json`.

6. **The permission ceiling answers first for `graftyard-agent`.** With the design's permissions (`contents: read`, `statuses: read`, `checks: read`, `actions: read`), 14 of the 42 Graftyard-run cells never reach `decide`, because GHES's "Resource not accessible by integration" comes first. Only a widened installation (grun-wide, 4,000 of 4,000 refused by `decide`) proves the rule itself. Proposed, in `build/BUILD-PLAN.md`, B0-36, "Measurement": "For the Graftyard-run kind, run once with the shipped permissions and once with an installation widened to every permission, and count a refusal from either"; and in `design/AGENT-LAYER.md`, "Failure modes", bad-config: note that `decide`'s refusals hold even when an admin widens a Graftyard-run installation.

7. **Which `graftyard/` writes and which status names.** "statuses and check runs whose context starts with `graftyard/`" leaves out commit status `context` versus check-run `name` and check-suite re-runs. The prototype refused both a status `context` and a check-run `name` starting with `graftyard/`, and counted `rerequestCheckSuite` as a workflow re-run. Proposed, in the agent block, `ActorKind` doc comment: "commit statuses whose `context`, and check runs whose `name`, start with `graftyard/`; workflow re-run includes `rerequestCheckSuite`".

8. **No GHES 3.22 GraphQL mutation exists for releases, statuses, or dispatch.** The row asks for each action "over git, REST, and GraphQL". GHES 3.22's GraphQL reference has no `createRelease`, `createCommitStatus`, `createRepositoryDispatch`, or workflow-dispatch mutation (checked against https://docs.github.com/en/enterprise-server@3.22/graphql/reference/, pages pulls, git, checks, repos, issues, commits, branches). The prototype covered releases with `createRef refs/tags/...` and statuses with `createCheckRun`. Proposed, in `build/BUILD-PLAN.md`, B0-36: "over git, REST, and GraphQL where GHES 3.22 has a surface for the action".

9. **`AgentGate` and who counts as a pusher.** "did not push to that head" is ambiguous between the current head commit's pusher and anyone who pushed to the PR branch while it was open. The prototype records every user who moved the head ref while the PR was open and excludes them all (the stricter reading), and it checks the requester through `AgentMeta.requester`. Proposed, in the agent block, `AgentGate` doc comment: "and did not push to the PR's head ref while the PR was open". Evidence: unit test "AgentGate: head-bound, …".

10. **The requester's approval and `AgentGate` for a vendor PR.** A vendor's PR carries `AgentMeta.requester` only when it sends the session header on `PrOpen`. Without it, `requester` is null and the requester's own approval would satisfy the gate. Proposed, in `design/AGENT-LAYER.md`, `AgentMeta` doc comment: "A confined App's PR opened without a session header takes `requester` from none and needs `extra_human_approvals + 1` approvals" (or require the header for confined Apps). [guess at the remedy]

11. **Session refs cannot be appended with plain git.** "Never in v0 or v1 advertisement" applies to receive-pack's advertisement too, so a client pushing to `refs/graftyard/sessions/<uuid>` a second time sends old = zero and is refused as stale (`fetch first`). The prototype measured this: the create was accepted, then 0 of 99 appends with plain `git push` (`results/raw/wp10-b037-*-summary.json`, `controls.append`). The controller pushes the log once at the end (`design/AGENT-LAYER.md`, journey A3, step 8), so this holds today, but "appends" in the agent block's `SESSION_REFS` comment cannot happen through standard git. Proposed, in the agent block, `SESSION_REFS` doc comment: "`graftyard-workspace` creates its task's session ref once, and a later update must name the current tip, which it learns from a v2 `ls-refs` with that `ref-prefix`, since receive-pack never advertises it". Or limit it to "creates, once".

12. **"Appends" and its owner check.** The design allows "appends by the install's `graftyard-workspace`" without saying whose session ref. The prototype allows only `refs/graftyard/sessions/<its token's task>`, only while that task is live, only create or fast-forward, and nothing else under `refs/graftyard/`. Proposed, the same comment: "except creates and fast-forwards of `SESSION_REFS<task>` by `graftyard-workspace` with that task's `task` claim while the task is live". Evidence: B0-37 `hostref` kinds.

13. **Hidden-ref listing versus want by object id.** `SESSION_REFS` governs advertisement and `ls-refs`. git's own v2 `fetch` serves a want by object id of a hidden tip (git's `uploadpack.allowAnySHA1InWant` is implied in v2), and v0 refuses it with "not our ref". The prototype measured both (`raw` probes in the B0-37 summary). Proposed, in the agent block, `SESSION_REFS` doc comment: "A v2 `fetch` of a session log's object id is served to anyone who can read the repository, as for any object; listing is the only gate". [inference: this matches GitHub, where any object in a readable repository is fetchable by id]

14. **What `ref-prefix ... starts with it` means.** "listed by v2 `ls-refs` only to a `ref-prefix` that starts with it" can be read as "a prefix that starts with `SESSION_REFS`" or "a prefix that the ref starts with". The prototype requires both: a session ref is listed only when some `ref-prefix` starts with `refs/graftyard/sessions/` and the ref starts with that prefix. So `refs/` (`--mirror`), `refs/graftyard/`, and `refs/graftyard/sessions` (no slash) list nothing, and `refs/graftyard/sessions/1111` lists matching sessions. Proposed, the same comment: "listed by v2 `ls-refs` only when one `ref-prefix` begins with `refs/graftyard/sessions/` and the ref begins with that `ref-prefix`". Evidence: B0-37 raw `ls-refs` probes; `git fetch '+refs/graftyard/sessions/*:...'` sends exactly `ref-prefix refs/graftyard/sessions/`.

15. **Other refs under `refs/graftyard/`.** `SESSION_REFS` is `refs/graftyard/sessions/`, but the host-owned rule covers all of `refs/graftyard/`. The design does not say whether `refs/graftyard/<other>` is ever listed. The prototype never lists it. Proposed, the same comment: "Refs under `refs/graftyard/` outside `SESSION_REFS` are never advertised or listed".

16. **Provenance linking for a final task.** "`decide` records `Session` only when the commit's pusher has a matching `AgentTask` or `AgentMeta`" does not say whether the task must be live. A Graftyard-run push with a final task is refused anyway, but a vendor may cite its own cancelled External task. The prototype links it, because the pusher's App created it, so it is not a forgery (control `vendor names its own cancelled External task`). Proposed, the agent block, `Provenance` doc comment: "a matching `AgentTask` of the pushing App, live or final".

17. **What "matching" means for `Graftyard-Session`.** The design says forged trailers are "shown unlinked after https scheme and host checks", but not how a value maps to a session. The prototype links only `https://<install host>/<owner>/<repo>/_graftyard/sessions/<id>` with the base repository's path (fork mode included, as journey A3 step 7 says), with no userinfo, query, or fragment, and only for an App pusher. A user token never links, even its requester's (`alice (T1's requester) names T1`). Proposed, the agent block, `Provenance` doc comment: "A `Graftyard-Session` value links only when it is exactly `https://<host>/<base owner>/<base repo>/_graftyard/sessions/<id>`, `<id>` is a task of the pushing App, and the pusher is that App's installation token".

18. **"A parse failure leaves it empty" has no bounds.** The prototype needed caps to make parsing total and bounded: the last 1 MiB of each message, 32 recognized trailers per commit, 1,024 bytes per value, 2,000 new commits per push, 64 KiB per note, and stripping of C0, C1, and bidi characters. It also had to choose git's trailer-block rule (last paragraph, all trailers or at least 25% with a recognized key). Proposed, the agent block, `Provenance` doc comment: "Trailers are read from the last paragraph of each new commit's message, as `git interpret-trailers --parse` does, capped at TRAILERS_MAX per commit and VALUE_MAX bytes per value, past which the rest is dropped and the push proceeds" [guess at the constants]. Also note that a commit with a NUL in its message, or a malformed author line, fails git's own `index-pack --strict` before parsing, so "zero pushes fail on parsing" holds only for objects that pass fsck (measured with `index-pack --strict` locally; the B0-37 generators avoid both).

19. **`refs/notes/ai` entries that are not notes.** The design says the notes update is parsed but not what counts. The prototype takes only blob entries whose path, with fan-out slashes removed, is 40 hex characters, records `AiNote { note }` for that commit, and skips the rest: gitlinks, nested trees, non-hex paths, the ref pointing at a blob, and 300-entry trees. It never fails the push. Proposed, the agent block, `Provenance` doc comment: "`AiNote` is recorded for each blob of the `refs/notes/ai` tree diff whose fan-out path names a commit object id; other entries are ignored".

20. **`refs/notes/ai` is outside every agent prefix.** An `ActorKind::Agent` cannot push `refs/notes/ai` because of the prefix rule, so `AiNote` comes only from humans and unconfined Apps. Proposed, the agent block, `ActorKind` doc comment: either "`refs/notes/ai` is allowed to an `Agent` for notes on commits under its prefix", or record in `design/AGENT-LAYER.md`, journey A6, that agent notes arrive only through the controller's human-side path.

21. **`AgentsExclusive` with an agent's own lease, and Exclusive leases of a holder whose task is final.** "refuses an `ActorKind::Agent` push whose `changed` paths overlap another holder's live Exclusive lease" leaves "another holder" undefined for an agent without a session. The prototype treats a lease as the pusher's own when its session equals the pusher's task, or its actor and session both match. A lease whose holder's task is final reads as released, which the lease comment says only for "cancelling or finishing", applied at `decide` time. Proposed, the agent block, `LeaseEnforce` doc comment: "another holder: a lease whose `session` differs from the pusher's task (or, with no task, whose actor differs)".

22. **`ChangedPaths` against two bases.** "against its merge base with the default branch and against the old tip" is a union. The prototype takes the union of both `git diff --name-only` sets, so an outsider commit already on another branch is caught (the "outsider-workflow" cells: 600 of 600 `Protected`), and a rebase that only drops commits still reports their paths. That is the stricter reading. Proposed, the agent block, `ProtectedHits` doc comment: "the union of both diffs".

23. **The classing trailer and admission for unflagged Apps.** "when an App token's push carries a trailer that classes it" covers any App. The prototype applies it to `graftyard-insights`, a non-agent App, as a unit test. It cannot decide whether an App can avoid Agent admission by omitting trailers, which is by design. No edit; recorded for the B0-33 owner.

24. **Fork mode merge base.** "`protected` and `changed` then take their merge base against the base's default-branch tip" means the fork's container must hold the base's objects. The prototype gives the fork the base's object directory as an alternate, which holds within one network. No edit; the base design's same-network forks already share packs.

25. **Receive-pack advertisement contains every ref, and rev-list `--not --all` does not scale.** Not a rule ambiguity but found while running: git's receive-pack marks new commits with `rev-list <tips> --not --all`. With about 5,000 refs, that walk took 3 s per push under load, and one pack per push without compaction made every git call slower. The prototype bounds the walk with the updated refs' old tips and the default-branch tip (enough for provenance), and repacks geometrically past 32 packs. Proposed, `design/DESIGN.md`, "Git cache shards (derived)", `validate` doc: "the new commits for `Provenance` are those reachable from the new tips and not from the updated refs' old tips or the default branch's tip; connectivity still uses the full ref set" [measured in this run, cause inferred].
