## The cause of the 2 s: a guessed read that `link` kept alive

`install_authz` (A) runs its `Placement` read and its fold read through `link`, on a guess of the install's
`Placement` record. A cold isolate holds no `Placement` answer, so the guess is the genesis `Names` record
(`at` 1). The install account's real row has `at` 5 (read from `names:24`), so the guess is always wrong on a cold
isolate. `link` then reads the fold again on the real record, but the guessed fold read stays alive: it is pinned in
`link`'s future until `link` returns. Both reads are write-class reads of one key, `rcache::AUTHZ` for the install
account. The read again found the guessed read in flight, waited for it, and took no answer from it, since a call
takes only answers of reads that start after it. The guessed read never ended while it was pinned, so the read again
waited out `BATCH_STALE`. That matches `rcwait` 1,800 to 1,940 ms on 24 of 27.

The bed did not show this. Its genesis `Names` record and the install's `Placement` row are the same, so the guess
was always right there.

**Fix, built on branch `cw-link-drop` (`abbc9a0b`, on main `5243ced8`), not deployed:** `link` drops a guessed read
that was not kept before it reads again.
- The regression test holds a guessed read that never ends and checks the read again starts with it dropped. It
  fails without the drop.
- Edge native tests pass, clippy (native and wasm32, with and without test-faults) is clean, and both edgeboot builds
  pass with 0 traps.

Expected effect: the 24 waits lose about 1.9 s each, so cold first POST front + gate falls to about 0.4 to 0.85 s, the
3 that did not wait [inference]. It needs its own edge day to measure, and none ran: this cell's clearance was one
edge day from main.
