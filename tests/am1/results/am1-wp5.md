## What was built

- `crates/api/src/trust.rs` adds `AGENT_MEDIA_TYPE`, `TrustView`, `Hidden`, `AuthorTrust`, `HIDDEN_CHARS`, and `Resource`.
  - `resource_of` lists the trust resources as REST path patterns. They come from the routes in the pinned `ghes-3.22` description whose 2xx body is an issue, a pull request, an issue comment, a review, a review comment, a release, a commit, or a check run, or a list of one of these.
  - `layer` returns the reply it was given unless one `Accept` range equals the media type. When it does and the route is a trust resource, the reply gets `Vary: Accept`, and each object of a 2xx JSON body gets `graftyard_trust`. `body` and `body_html` are not touched.
  - `visible` ports the M0-WP13 prototype (`tests/m0/src/agent/trust.ts`), the code that passed L0-09. On all 200 L0-09 payloads it returns the prototype's `visible` and `hidden` exactly [measured, `crates/api/tests/trust_l009.json`, generated by running the prototype under node]. It drops more than the prototype in three forms. A hidden character in a link destination is dropped, whether raw or written as a reference. A raw hidden character in a kept `href` or `src` is dropped. A reference definition's title on a CRLF line is dropped and counted.
  - `TrustView::of`, `issue`, `comment`, `review`, `release`, and `check_run` build a view from fold rows, for MCP and the controller's prompt later.
- `workers/edge/src/api.rs` changes in 4 lines. `rest_repo` reads `Accept` and hands its reply to `trust::layer`. GraphQL, LFS, uploads, and codeload do not go through the layer.

## Where the view shows today

Of the trust resources, the hosted edge serves only releases over REST: `GET /releases/{id}`, `GET /releases/tags/{tag}`, `POST /releases`, and `PATCH /releases/{id}`. gh reads issues, pull requests, and comments through GraphQL, and the design gives GraphQL no trust field. Each other REST route gets the view through the same `layer` call once it is served. The tests check those routes with GHES-shaped objects [inference: the field is added to the rendered object, so it does not depend on the route's handler].

## Author trust

`can_push` is true when the author owns the repository or holds `write` or more. The test directory includes a triager, a maintainer, a reader, and an account with no grant, and the viewer is a writer. That catches a view built from the viewer's permission instead of the author's.

These parts of `AuthorTrust` are fixed for now:

- `is_agent` is always false, because `AgentApp` rows come in AM1-WP2.
- `first_contribution` is always false, because no fold row records one.
- A commit's author is a git claim, so no account vouches for it, and a commit is never trusted. The M0 prototype did the same.
- A check run is written by its App, so its author is a bot.
